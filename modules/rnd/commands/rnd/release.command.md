name: rnd/release
description: release it — plan a version and write its notes from the changes it ships, stop for a person's tag at the cut, then confirm the registries answer it and stamp deployed_on on every request it carries
argument-hint: <rnd/releases/id | rnd/change-requests/id>
---
load the `rnd-release` skill. for $ARGUMENTS (a change request: its `release`): ask `dt next` which step is open. plan — set `release` on each verified change request and fixed issue it ships, write the notes from their bodies. cut — run the repo's release gates and quote each exit code, then STOP: tagging is publishing and the tag is a person's; after their tag, record `status=cut` with `tag`, `repo` and `cut_on`. publish — check every registry answers the exact version, set `status=published` with `published_on` and one `published_to=` per URL, stamp `deployed_on=<published_on>` on every change request it carries and the tag on every issue's empty `fixed_in`. a release already published whose `dt next` names the stamp step: only that last half — stamp each carried request still without `deployed_on` and each issue without `fixed_in`. a rolled-back release whose `dt next` names the rollback step: move each accepted request and each issue off it (`release=` the next planned one or empty), clearing `deployed_on` and `fixed_in`. each request's next gate is its live acceptance review, never yours. commit by id.
